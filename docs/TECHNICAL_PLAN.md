# 赵俊莉教授学术主页技术方案

## 1. 建设目标

建设一个以学术成果、研究方向和团队招生为核心的教授个人主页。视觉参考 Stanford、MIT 教授主页的信息密度和编辑感，但不复制具体页面。核心原则是：专业、克制、内容优先、易维护、移动端可读。

## 2. 技术决策

| 层级 | 方案 | 原因 |
| --- | --- | --- |
| 界面 | React 19 + TypeScript | 组件化、类型安全，方便长期维护 |
| 样式 | Tailwind CSS 4 | 快速建立统一的学术视觉系统与响应式布局 |
| 路由/构建 | Vinext + Vite | 文件式路由、快速开发反馈、支持静态优先输出 |
| 内容 | 本地结构化 TypeScript 数据 | 首版无需 CMS，部署简单，内容可审查 |
| 质量 | ESLint + TypeScript + 构建检查 | 在合并前发现类型、语法和可访问性问题 |
| 部署 | 静态优先、Cloudflare Worker 兼容 | 全球访问快，运维成本低 |

首版不引入数据库、登录系统、CMS 或 3D 展示。如新闻更新频率明显增加，再在不改变页面组件的前提下接入 Headless CMS。

## 3. 信息架构与路由

| 路由 | 栏目 | 主要内容 |
| --- | --- | --- |
| `/` | Home | 姓名职称、简介、核心研究方向、精选论文、最新动态 |
| `/about` | About | 教育与工作经历、学术服务、个人简介、CV 下载 |
| `/research` | Research | 研究主题、方法、应用场景、代表性成果 |
| `/projects` | Projects | 项目名称、来源、编号、周期、角色与状态 |
| `/publications` | Publications | 论文列表、年份/类型筛选、DOI/项目/下载链接 |
| `/awards` | Awards | 人才称号、学术奖励、教学奖励、年份 |
| `/team` | Team | 教师、博士生、硕士生、校友及招生信息 |
| `/news` | News | 新闻列表与新闻详情 |
| `/contact` | Contact | 邮箱、办公地点、学院链接、地图与合作说明 |

## 4. 目录设计

```text
zhaojunli-homepage/
├── app/                         # 路由入口与全局样式
│   └── (site)/                  # 公共网站路由组
│       ├── about/
│       ├── research/
│       ├── projects/
│       ├── publications/
│       ├── awards/
│       ├── team/
│       ├── news/
│       └── contact/
├── components/
│   ├── layout/                  # 页头、导航、页脚、移动端菜单
│   ├── sections/                # 业务内容区块
│   └── ui/                      # 通用基础组件
├── content/                     # 教授、论文、项目、团队、新闻数据
├── lib/                         # 排序、筛选、SEO 等纯工具
├── types/                       # 内容模型与公共类型
├── public/
│   ├── images/
│   │   ├── profile/
│   │   ├── research/
│   │   ├── team/
│   │   └── news/
│   └── documents/                # CV 和经授权的公开附件
├── docs/                        # 方案与内容维护文档
└── tests/                       # 构建与关键页面检查
```

`app` 只负责页面组装，`components` 负责展示，`content` 负责事实数据，`types` 负责数据约束。这样可以将内容更新与视觉开发分离。

## 5. 内容模型

第二阶段为以下数据建立 TypeScript 类型：

- `ProfessorProfile`：中英文姓名、职称、学院、简介、经历、联系方式、学术主页链接。
- `ResearchArea`：名称、摘要、关键词、图片、关联论文。
- `Project`：项目名称、来源、编号、级别、周期、负责角色、状态。
- `Publication`：标题、作者、会议/期刊、年份、类型、卷期页码、DOI、PDF、代码与精选标记。
- `Award`：名称、授予机构、年份、类型、级别。
- `TeamMember`：姓名、角色、研究方向、年级、照片、个人链接、当前/校友状态。
- `NewsItem`：标题、日期、摘要、正文、封面、类别、外部链接。

列表在数据层保留完整信息，在展示层完成按年份、类型和状态的排序与筛选。

## 6. 视觉与交互原则

- 配色：以青岛大学深蓝/藏青为主色，米白与中性灰为背景，用低饱和金色做少量强调。最终色值需与学校视觉规范核对。
- 字体：中文优先系统黑体，英文标题可搭配克制的衬线体；不依赖远程字体才能正常阅读。
- 版式：桌面端使用窄至中等宽度内容栏，建立清晰的类型层级和留白；避免过度大屏、卡片堆叠和装饰动画。
- 交互：只保留导航、筛选、展开和必要的过渡反馈；尊重 `prefers-reduced-motion`。
- 图片：优先使用经授权的教授照片、团队照片和科研图像；不使用无意义的素材图填充。

## 7. 响应式与可访问性

- 采用移动端优先布局，在约 768px 切换为桌面导航和多列内容。
- 触摸目标不小于 44px，长论文标题和中英文混排允许自然换行。
- 使用语义化标签、可见焦点、跳转到主内容链接、图片替代文本和正确标题顺序。
- 文本与背景对比度以 WCAG 2.2 AA 为最低目标。
- 桌面端、平板和手机端均检查导航、表格/列表、联系链接和长文本。

## 8. SEO、性能与安全

- 每个栏目提供独立标题、描述和规范链接，加入 `Person`、`ScholarlyArticle` 等结构化数据。
- 生成 `sitemap.xml`、`robots.txt` 和社交分享元数据。
- 图片提供明确尺寸，并根据展示尺寸输出 WebP/AVIF；首屏以外图片懒加载。
- 尽量使用服务器组件和静态 HTML，仅对菜单、筛选等局部交互启用客户端 JavaScript。
- 不在前端暴露私密电话、未授权照片、未公开项目材料或可利用的表单密钥。

## 9. 开发阶段

1. **基础结构（当前）**：初始化工程、定义目录、路由、内容模型和质量标准。
2. **内容建模**：收集并核验教授资料，建立类型与本地数据文件。
3. **设计系统**：完成颜色、字体、间距、栅格和通用组件。
4. **页面实现**：先 Home / About / Research，再完成成果、团队、新闻与联系页。
5. **验证与上线**：内容校对、响应式和无障碍检查、构建验证、SEO 检查和部署。

## 10. 验收标准

- 九个栏目均可直接访问，且导航一致。
- 360px 宽手机屏无横向滚动，桌面端在常见尺寸下保持良好阅读宽度。
- 论文、项目、团队和新闻可通过数据文件更新，无需修改列表组件。
- 所有外部链接、邮箱、DOI/PDF/CV 均经人工校验。
- 键盘可完成导航与筛选，关键页面符合 WCAG 2.2 AA 目标。
- 生产构建通过，没有类型错误和明显的浏览器控制台错误。
